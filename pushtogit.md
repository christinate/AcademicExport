# Git commit allowlist

Only the files listed below may be staged, committed, or pushed. Update and validate this list whenever a build input, dependency, test, repository file, or release artifact is intentionally added or removed.

Temporary files, rendered QA documents, local vault data, dependency installations, coverage, caches, and ad-hoc scripts are intentionally excluded. Never use `git add .` or `git add -A` in this repository; stage the paths from this list explicitly and verify the staged file list before every commit.

## Release attachments

These files are attached to a GitHub Release whose tag matches `manifest.json`. `manifest.json` and `styles.css` are also repository files listed above. `main.js` is generated by `npm run build`, remains ignored by Git, and must never be staged or committed.

```release-attachment
main.js
manifest.json
styles.css
```

## Pre-commit procedure

1. Run `npm test`, `npm run lint`, and `npm run build`.
2. Confirm every path in this allowlist exists.
3. Stage only the exact paths above.
4. Compare `git diff --cached --name-only` to this allowlist.
5. Unstage and investigate anything not listed before committing.
6. Confirm `main.js` exists after the build but is not staged.
7. For a GitHub release, create a tag matching `manifest.json` and attach `main.js`, `manifest.json`, and `styles.css` to the release.
